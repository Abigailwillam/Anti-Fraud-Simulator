# 反诈演练 · 案例库、互动模式与诈骗辨析

一个**双击即可运行**的反诈骗意识训练网页。首页三个入口：

- **诈骗案例库** —— 10 大类、30 条案例，可搜索、可分类浏览、可展开看完整手法拆解
- **互动模式** —— 模拟一部手机，在微信里和诈骗方「好友」对话，规则引擎实时计算风险指数
- **诈骗辨析** —— 上传聊天记录或截图，判断对方是不是骗子，输出结论、风险等级、可疑点与防骗建议

产物：`dist/scam-sim.html` —— 单文件，零依赖，无需服务器。

## 使用

双击 `dist/scam-sim.html`，从首页选入口。

## 一、诈骗案例库

**搜索栏**（顶部）：输入关键词即时过滤，支持空格分隔多关键词（AND 关系）。匹配范围是标题、摘要、分类名、标签、以及正文各处（手法拆解、典型话术、破绽、处置建议）。

> **搜索与分类的关系**（容易误解的一点）：
> 搜索**始终作用于全库**，不管你当前停留在哪个分类。切分类不会缩小搜索范围，
> 只有清空搜索框才会回到「按分类浏览」。
> 这一点由 `searchCases(keyword)` 的函数签名保证——它根本没有分类参数，从类型层面就不允许传入。
> 界面上会明确写「在全库 30 条案例中匹配到 N 条」，不让你猜。

## 二、互动模式

功能与之前完全一致：模拟手机 → 桌面 → 微信 → 好友列表 → 聊天。

- 4 个剧本：冒充公检法、虚假投资、冒充客服、刷单兼职，各含 4 个推进阶段
- 每阶段带话术池、施压话术、**破绽提示**、防范建议，部分阶段触发微信原生动作（发链接、屏幕共享、拉群）
- 规则引擎实时检测危险行为（给卡号、说验证码、同意屏幕共享、发收款码…）并计算风险指数 0-100
- 结束（说「我要报警」或点「拉黑」）后生成复盘报告：暴露的风险行为、阶段推进复盘、走过的阶段里存在的破绽、完整聊天记录

### 规则控场，AI 只负责说话

| 职责 | 由谁决定 |
|---|---|
| 剧情阶段 / 风险评分 / 终止判定 | **规则引擎**（确定性） |
| 把话术说成人话、贴合人设 | **AI**（可选） |

演练结果必须可复现、可评分，所以换任何模型都不影响评估口径。
测试里专门有一条断言：**无论模型说什么，连续质疑都不会推进阶段。**

设置面板在侧栏（不在手机屏幕上），支持任何 OpenAI 兼容的 `/chat/completions` 接口。
AI 越界有三层防护（prompt 硬约束 → 输出正则校验 → 二次脱敏），任一触发或网络失败都自动降级为内置话术。

## 三、诈骗辨析

上传一段聊天记录，得到「是 / 否 / 无法判断」的结论、风险等级、逐条可疑点说明与防骗建议。

### 上传入口

| 类型 | 支持格式 | 大小上限 |
|---|---|---|
| 文本 | `.txt` `.md` `.log` `.csv` `.json` | 200 KB |
| 图片 | `.jpg` `.jpeg` `.png` `.webp` `.bmp` `.gif` | 5 MB |

支持点击选择、拖拽放入，以及直接粘贴文字。粘贴内容与上传文件内容会合并后一并分析。
格式与大小上限由 `engine/detect.js` 的 `UPLOAD_SPEC` 单一定义，界面提示直接渲染它，不会与实际校验脱节。

图片不做本地 OCR（纯前端单文件无此能力），而是作为多模态 `image_url` 交给模型识别；
因此**图片分析必须启用支持视觉的模型**。模型不支持视觉、或这张图实在难辨时，
结果页会给出醒目的失败横幅与可操作指引，而不是一个含糊的「无法判断」。
辨析屏的「测试视觉」按钮可用一张 1×1 测试图判定当前模型到底能不能读图。

### AI 配置（两屏各自可直接配置）

辨析屏**自带完整的 AI 配置面板**，无需跳转到互动模式：启用开关、Base URL、API Key、模型、温度、
「测试连接」「清空」都在辨析屏内就地完成。

配置的数据结构分成两层，这是理解本模块的关键：

| 字段 | 存放 | 是否两屏共用 |
|---|---|---|
| `baseUrl` / `apiKey` / `model` / `temperature` | `localStorage: scamsim.ai.v1` | **共用**——在任一屏修改，另一屏的输入框立即同步显示 |
| `enabled` | 同上 | 互动模式专用：AI 替我生成对话话术 |
| `analyzeEnabled` | 同上 | 辨析专用：AI 参与研判，补充规则未覆盖的语义线索 |

**为什么连接参数共用、开关分开**：连接参数是「连哪个服务、用哪个模型」，两屏理应一致；
开关的语义不同（一个决定「AI 替我说话」，一个决定「AI 参与研判」），
共用一个开关会导致用户在辨析屏开开关时意外改变互动模式的行为。

由此得到的行为保证（已有端到端测试覆盖）：

- 只开辨析开关 → 辨析调用 AI，互动模式仍走内置知识库话术
- 只开互动模式开关 → 互动模式调用 AI，辨析完全不发请求（离线规则分析）
- 开关打开但配置不完整 → 引擎状态条明确提示「配置不完整，本次按本地规则引擎分析」，不静默降级
- 任意一屏「清空」→ 同时重置两屏的开关与连接参数

实现方式是一个可挂载的 `mountAIPanel()` 组件（`src/page.html`），两个面板实例共享同一个 `aiCfg` 对象，
任一面板改动后调用 `renderAIFields()` 同步另一屏的输入框。

### 常见模型的图片输入支持（按官方能力表）

截图辨析能不能用，取决于模型支不支持图片输入。官方口径如下：

| 模型 | 图片输入 | 说明 |
|---|---|---|
| `deepseek-flash` | ✅ 支持 | DeepSeek 官方唯一支持图像理解的模型（V4.1-Flash） |
| `deepseek-v4-pro` | ❌ 不支持 | 纯文本模型，收到图片只会得到「unsupported image」 |
| `deepseek-chat` / `deepseek-reasoner` / `deepseek-r1` | ❌ 不支持 | 纯文本模型 |
| `gpt-4o` / `gpt-4o-mini` / `gpt-4.1` / `gpt-4.5` / `gpt-4-turbo` | ✅ 支持 | OpenAI |
| `qwen-vl` / `qwen2.5-vl` / `qwen3-vl` | ✅ 支持 | 阿里通义 |
| `gemini-*` / `claude-3+` / `glm-4v` / `kimi-vl` | ✅ 支持 | 各家视觉系列 |
| `gpt-3.5-turbo` | ❌ 不支持 | 老模型，不支持视觉 |

DeepSeek 用户把模型填成 `deepseek-flash` 即可；本工具在 AI 面板里会实时提示当前模型
支不支持图片输入，并提供一键切换。

> DeepSeek 官方接口默认开启「思考模式」，思维链会占用 `max_tokens` 预算，
> 预算只够答案时模型会「只有思考没有答案」。本工具对 DeepSeek 官方接口自动带上
> `thinking: {type: "disabled"}`（省一半 token、延迟更低），其他厂商的接口不受影响。

### 结论口径

与本项目「规则控场，AI 只负责说话」的分工一致，辨析模块同样分两层：

| 职责 | 由谁决定 |
|---|---|
| 特征命中、风险分、等级判定、结论仲裁 | **规则引擎**（确定性） |
| 语义研判表述、规则未覆盖的语义线索 | **AI**（可选） |

- 规则分 ≥ 25 判为「是」；规则零命中且 AI 未提出语义线索判为「否」；其余为「无法判断」。
- **规则强信号不可被 AI 推翻**：规则分 ≥ 45 时 AI 判「否」会被强制改为「是」，且冲突写入结果的说明区，不静默改写。
- AI 判「是」而规则零命中时保留结论，但置信度被压到 ≤ 72 并提示人工复核。
- AI 输出须通过 `parseAnalysis()` 严格 JSON 校验，非法即丢弃；输出含可执行诈骗操作指引时按越界拒绝。
- AI 超时、失败、越界、结构非法 —— 全部降级为纯规则结论，功能不中断。

### 异常处理

| 场景 | 提示与出口 |
|---|---|
| 格式不支持 | 列出支持的全部格式，附「换文件」按钮 |
| 超过大小上限 | 说明实际大小与上限，附「换文件」按钮 |
| 文件读取失败 | 说明可能是被占用或权限不足，附「重新读取」 |
| 内容为空 / 过短 | 说明有效字数，附「重新选择文件」 |
| **图片读不出** | 顶部红色横幅「模型没能读出这张截图，本次结论不可用」+ 可操作指引（换支持视觉的模型 / 裁剪图片 / 改用文字分析）+「重新分析」「改用文字分析」「改用 deepseek-flash 并重试」三个出口 |
| **模型不支持视觉** | 分析前就被拦下（不消耗请求），横幅直接点名「请把模型改成「deepseek-flash」后重试」 |
| AI 超时 / 请求失败 | 展示降级原因，仍给出规则层结论 |
| AI 输出非法或越界 | 展示拒绝原因，仍给出规则层结论 |

所有错误态都提供「重试」与「清空重填」两个出口，不会把用户堵死在错误页。

### 图片分析的关键设计

截图分析失败的原因往往不是「网络问题」，而是三类完全不同的情况。本模块用几处设计把它们区分开：

**1. 前置视觉自检闸门：先证明模型能读图，再让它分析**

这是最重要的一处。看不见图的模型**照样能输出一个像模像样的结论**——
实测 `deepseek-v4-pro` 收不到图时，照样编出了「我是客服」「投资返利」「转账到指定账户」
这种截图里根本不存在的引文，还给了 85 分高危。对反诈工具来说，**编造的证据比「无法判断」危险得多**：
前者会让用户以为证据确凿而继续转账，后者至少在提醒他小心。

所以图片研判改成三步：

| 步骤 | 做什么 | 不通过时 |
|---|---|---|
| ① 查表 | `describeVisionSupport(model, baseUrl)` 判断模型名是否已知不支持视觉 | 直接拦下，**一个请求都不发** |
| ② 自检 | 发一张四宫格测试图（红/蓝/绿/黄），要求按「左上、右上、左下、右下」报出颜色 | 明确说读不了 → 拦下；答错 → **失败关闭**，不采信任何图片结论 |
| ③ 研判 | 通过自检才发真正的分析请求 | 正常出结论 |

自检图为什么不用「1×1 纯白图问什么颜色」：那种问法瞎猜就能答对（实测纯文本模型也能顺口答出个颜色），
区分度太差。四宫格要求报出**四个颜色的顺序**，瞎猜恰好排对的概率只有 1/256。
实测 `deepseek-flash` 稳定答「红色、蓝色、绿色、黄色」，`deepseek-v4-pro` 答成「灰色、灰色、灰色、灰色」。

**2. 模型能力在填表时就提示**

AI 面板里实时显示当前模型支不支持图片输入：
不支持 → 黄色警告 + 「换成 deepseek-flash」按钮（DeepSeek 官方接口下可直接换）；
支持 → 绿色对勾；认不出 → 提示用「测试视觉」验证。
选了图片时若模型不支持，当场就警告，不等分析跑完。

**3. 输出预算按输入类型给足（`max_tokens`）**

视觉模型要先「读图」再输出 JSON，长截图 / 多宫格拼图的读图过程本身消耗大量推理额度。
现在：纯文本 2000，截图 4000（`engine/detect.js` 的 `TEXT_MAX_TOKENS` / `IMAGE_MAX_TOKENS`）。
纯文本从 800 提到 2000，是因为接口默认开思考模式时思维链也吃这份预算，
预算只够答案的话，模型多想两句就会把答案挤空，表现为「接口未返回可用文本」。

**4. 图片场景有专用提示词（`buildImageInstruction()`）**

聊天截图常见形态是**多屏对话拼在一起的长图**，每屏字号很小。
提示词要求「逐格分别阅读每一屏」「只要能读出部分内容就基于读到的内容判断」，
但同时**堵住了编造的源头**：明确要求「只有确实在图里看到了对应的话术才能用该特征类型」
「看不到图就把 verdict 设为 unknown」——
早先的提示词只强调「不要放弃」，把纯文本模型逼到「必须给结论」，
它就会顺着提示词里的特征 id 列表编出并不存在的引文。

**5. 读图失败与「结论是未知」严格区分**

**3. 读图失败与「结论是未知」严格区分**

模型说「读不到图」是一次**分析失败**，不是一个「无法判断」的结论。
`saysCannotReadImage()` 识别这类表述后，结果页顶部会出现醒目的失败横幅，
并区分两种成因：

- 模型表示不支持 / 无法处理图片 → 建议换支持视觉的模型（gpt-4o、gpt-4o-mini、qwen-vl 等）
- 图确实难辨 → 建议裁剪到单个对话窗口、提高清晰度，或直接改用文字分析

**「测试视觉」按钮**（辨析屏 AI 面板内）用一张 1×1 测试图问模型「这是什么颜色」，
以此判定**模型本身是否支持图片输入**——一步就能把「模型不支持」与「这张图难辨」分开，
不用猜。

### 与已有功能的复用

- **复用 AI 配置**：辨析与互动模式共用同一份连接参数（同一 localStorage 键）与同一套 `callChat` / `validateSettings`；
  **两屏各自内置配置面板，无需互相跳转**（见上一节）。
- **复用案例库**：每类特征带 `catId`，结果页「看同类案例」直接跳转案例库并定位到该分类。
- **复用设置面板模式**：两处面板用同一个 `mountAIPanel()` 组件渲染，样式类（`.aifields` / `.switch` / `.fld`）完全一致。
- **不落盘**：上传内容只存在于内存与本次请求，不写 localStorage，不做持久化。

## 界面适配

## 局限

- 案例库为静态内置数据（30 条），不含真实案件当事人信息。
- 内置话术模式下，同一阶段的多次回复会有重复；开启 AI 可缓解。
- 风险检测基于关键词，对刻意隐晦的表述（如只给卡号后四位）不敏感。
- **辨析模块同样基于规则表 + 模型语义判断，不是法律意义上的鉴定结论**；重要决策请以人工核实与官方通报为准。
- 辨析模块不做本地 OCR：图片必须由支持视觉的模型识别。模型不支持视觉时，
  分析请求**根本不会发出**（本地按模型名拦下），结果页直接给出「请把模型改成 deepseek-flash」。
- **视觉自检是「失败关闭」的**：模型名认不出、又没通过四宫格自检时，本工具**不采信**它的图片结论——
  因为看不见图的模型会编造出「我是客服」「投资返利」这种图里根本不存在的引文，
  假证据比「无法判断」更容易让人上当。代价是：万一某个视觉模型答题方式古怪导致自检没通过，
  也会被拦下，此时换用「测试视觉」确认过的模型即可。
- **图片场景下本地规则层无法参与**：规则引擎读不到图里的文字，图片结论完全来自模型，
  因此结果页标注「结论完全来自 AI 视觉识别，请以人工复核为准」。
  若要获得规则层的交叉验证，可把聊天文字粘贴进文本框再分析一次。
- 结论为「无法判断」时，风险等级显示「**无法评估**」而不是「未发现风险」——
  没读懂不等于没风险，这一条是刻意设计的，避免给出虚假的安全感。
- 辨析的 14 类特征与案例库分类是映射关系，不构成完整的诈骗类型学；新型手法需靠 AI 补充线索兜底。
- API Key 存在 localStorage，明文可被同源脚本读取。仅在自己信任的机器上使用。
- `file://` 下直连第三方 API 可能被对方的 CORS 策略拦截（浏览器限制，非代码问题）。若 Key 无效却连不上，可 `npx serve` 起本地服务再打开。
- 聊天记录会随 AI 请求发送给所配置的模型服务，演练中请勿输入真实个人信息。**辨析功能同理：上传的聊天记录会发往你配置的模型接口，请勿上传含真实个人信息的记录。**
- 复盘报告与辨析结果只在本页生成，不做持久化存储。
